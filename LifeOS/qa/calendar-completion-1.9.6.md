# Calendar workflow completion

Planner supports all-day appointments with inclusive first/last day controls, multi-day display and exclusive midnight storage. The day view, dashboard and morning brief identify all-day events. Timed appointments remain unchanged when upgrading. New migrations add the all-day field and deletion tombstones without editing applied migrations.

ICS preview/import/export retains date-only values and calendar dates, including the RFC5545 one-day default when a date-only event omits DTEND. Mixed date/timed boundaries and invalid dates reject. Recurring ICS still requires individual expanded instances. Google imports/exports date-only ranges; Outlook uses isAllDay and midnight in one provider time zone. When Graph renders a non-UTC all-day boundary in UTC, the adapter requests the event in its original time zone before selecting dates.

Local cancellation/deletion publishing has a new separate default-off control. Existing new/edit publishing preferences are not expanded silently. Deletion tombstones keep provider identity and last-seen version after the local row is deleted. Conditional DELETE checks preserve remote changes and treat already-removed records idempotently. Provider conflicts stay visible in history. Attendee-bearing meetings reject automatic deletion because deleting them can send cancellation messages; use the provider calendar for those meetings.

Targeted isolated verification:

- `php tests/calendar_completion.php`: 25 checks, including multi-day boundaries, date validation, ICS round trips, upgrade-compatible timed hashes, default-off deletion consent, tombstones, stale remote versions, idempotent deletes and database integrity.
- `php tests/connectivity.php`: 66 existing service checks.
- `python tests/connectivity_http.py`: 40 checks, including confirmed all-day import and date-only export.
- `python tests/connectivity_worker.py`: 11 offline transport tests for Google/Outlook date boundaries, original-zone fetch, conditional writes/deletes, exact outgoing DELETE/If-Match headers, provider conflicts, missing versions, already-removed events and attendee protection.
- `python tests/calendar_completion_ui.py`: actual Chromium create/edit, all-day/timed field switching, keyboard Space, persisted consent, narrow layout and Sinhala/Tamil labels. Evidence path/count is printed by each run under `tests/.tmp/calendar-completion-ui-*`.

No personal calendar account was contacted. Real registered-provider sign-in/refresh/permissions and provider-specific DELETE behavior still require configured account acceptance. The transport tests prove the emitted contract and safe handling of provider rejections, not live provider approval. Microsoft Learn's endpoint references explicitly expose the optional If-Match parameter for both default and selected-calendar event DELETE routes; Graph's error reference defines mismatching preconditions as HTTP 412. Fluent human Sinhala/Tamil wording review remains separate.

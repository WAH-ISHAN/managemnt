# LifeOS 1.9.4 — accounts, administration and OEM activation

Implemented email/password registration/login in the desktop and Orean account portal, dedicated LifeOS administration on the existing Orean VPS, hashed OEM keys bound atomically to one account/device, signed offline leases, feature permissions, suspension, license revocation, audit history and one-time account recovery codes. Core routes, native desktop-panel aliases, AI queuing, module visibility and background routines respect entitlements. Commercial enforcement persists outside replaceable application files. Personal source builds retain optional activation; the customer installer was built with commercial enforcement enabled.

The signing private key exists only in the root-only server environment. Desktop files contain its public key. Personal workspace data is not synchronized. The app sends explicit account/activation fields, and AI still sends only the typed conversation/context deliberately supplied by the user. An account/license never bypasses the AI service's quotas or selects a paid model silently.

The owner explicitly approved bundling the already-installed OpenCode 2.2.5 runtime and private Python helper. Both are under `scripts/ai-runtime`, ahead of system tool lookup. Python import paths exclude user packages. No model weights or new local AI runtime downloads were used. CI pins the same approved archive and published SHA-256 for future reproducible packaging; Python/OpenCode notices accompany the payload. The installer continues to include the offline Windows WebView2 prerequisite.

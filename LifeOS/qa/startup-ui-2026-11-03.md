# Startup and UI improvements — 2026-11-03

The native Windows launcher now displays the existing LifeOS logo with a short eased entrance, a loading arc, “Welcome to LifeOS” and a Colombo-time greeting. Morning is 05:00–11:59, afternoon 12:00–16:59 and evening otherwise. It waits for successful application navigation and then fades out; an error closes the overlay before displaying the startup error. It runs once on a normal process launch, before the existing welcome/PIN flow. Windows reduced-motion preferences suppress the animated entrance. Diagnostic runs bypass the overlay.

UI improvements: modules without a routes file retain services/migrations but are hidden from navigation until ready; Capture shows a pending count and an explicitly described input; priority labels have stable form values; planning has clear empty states; removing a pinned block is visibly disabled until it is unpinned. Integration worker, OAuth, CLI and tracking helpers are now included by the installer build.

Verified: launcher build with zero warnings/errors; `tests/Startup-Welcome.ps1` passed 11 greeting boundary, timezone rollover and actual Windows form lifecycle checks. The captured `tests/.tmp/startup-welcome/welcome.png` was opened and visually inspected. `tests/extensions_ui.py` passed 23 Chromium workflow/layout checks; module loading 12 and planning/trends 40 passed. These checks used disposable data.

The broader native preflight is **not approved**: an initial run found navigation to a module with no routes, addressed by the navigation change; a subsequent run failed its native window-edge resize check. This failure remains recorded in `tests/.tmp/ui-improved-native.json`. No claim of complete native lifecycle or installer installation acceptance is made. Ollama installation/configuration is explicitly deferred at the user's request. Full application translation, isolated native browser profiles and real external account/model acceptance remain separate outstanding work in the core extensions report.

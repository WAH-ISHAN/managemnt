# Workspace delivery and reviewed replacement — LifeOS 1.9.6

Implemented **Devices & privacy → Continue on another computer**. After pairing, fingerprint comparison and explicit approval to share private records/documents, the resident runner delivers changed workspace snapshots through an existing external/shared folder. The receiver lists paired incoming snapshots and requires authenticated review, per-record-group additions/changes/removals, an exact **REPLACE** confirmation, and a fresh unchanged local revision. Nothing received is applied automatically.

This completes automatic encrypted snapshot delivery with reviewed full-workspace replacement. **It does not implement concurrent field-level whole-workspace merging.** Manual task/selected-record merges remain separate workflows. Physical USB/cloud client transfer between two real computers is not claimed by the local acceptance below.

The sender uses a consistent `VACUUM INTO` database snapshot, sanitizes that disposable snapshot without changing source records, then uses pairwise X25519-derived keys and the existing authenticated streaming backup format. Filename sender/recipient/creation/id fields must match the authenticated header; the review displays the authenticated sender and fingerprint. Only verified, atomically published ciphertext reaches the selected folder. Three outgoing snapshots per computer pair are retained. A stopped/asleep computer does not run background delivery.

Exports contain built-in personal/business records and uploaded files, including private finances, notes and mood records after deliberate sharing approval. Configured credentials, settings, profile/module preferences, device pairings, browser/AI account stores, API tokens, connection history/mappings, trusted code records and executable automation definitions are excluded. User-entered note/document content is shared as entered; typed secrets are not automatically redacted.

On replacement, local credential ciphertext/PIN/security preferences, profile/module settings, trusted code, pairings and automation definitions stay local. Jobs and write authority are paused before they can act on incoming numeric record IDs: automation rules, approved macros, financial recurrences, planning/archive/rescheduling, university/calendar/mail jobs, tracking and automatic onward workspace sharing. Existing scoped API tokens expire. A local workspace generation invalidates every previous browser session's forms, prepared previews, website-session mappings and CSRF tokens. A PIN-protected profile must unlock again. Previously approved recipients must be deliberately approved again before newly received records are forwarded.

The existing encrypted restore journal preserves both the previous database and uploaded files under `data/backups/before-encrypted-restore-*` before replacement, and recovers both after interruption. Schema, archive bounds/hashes/paths, document references, recipient/authentication, replay, revoked peers and stale reviews are checked before user-data mutation. Running Focus/Work timers are refused on either side. Snapshot compatibility requires matching module/migration versions.

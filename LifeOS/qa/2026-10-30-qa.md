## Calendar changes and defects caught

The new university calendar adapter copies only lecture metadata from a separate NIBM WebView. Sign-in and refresh credentials remain in the NIBM origin. The local import validates the selected batch, window, IDs, statuses and dates before its database transaction. The window covers the previous month through six upcoming months. It synchronizes while LifeOS is open and unlocked; email/OTP authentication is completed by the user. [Setup and boundaries](nibm-calendar.md).

QA found and fixed these concrete failure paths:

- An empty JSON object decoded as an empty PHP array could have cancelled saved lectures. Only a real JSON array can represent a complete snapshot now.
- Invalid empty refreshed credentials could overwrite usable university storage. Token validation now happens before saving or retrying.
- A delayed sign-in window initialization could reopen after pause/PIN lock. A generation check prevents that continuation from showing the window.
- Explicit failure/pagination/incomplete-response metadata is refused instead of being treated as a full calendar snapshot.

`tests/uni_calendar_upgrade.php` verifies migration from the real pre-calendar schema, preserving all prior user-table schemas/rows and migration history, with repeat migration, first import and restart checks. Existing migrations were not edited.

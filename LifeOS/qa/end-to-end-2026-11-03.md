## Whole-pool automatic AI routing

Removed the three-model attempt limit and the preference that pinned new questions to the last successful model. Every verified zero-cost text model in the installed runtime's catalog can now receive a request. Successful questions rotate through the pool; failed models have a five-minute cooldown, and fallback tries another eligible model without repeating a model within the same request. Catalog pricing expires after five minutes, is refreshed once during fallback, and is invalidated if refresh fails. All input/output/cache pricing tiers must still be zero. Generation attempts each have at most 20 seconds within a 90-second discovery/generation budget. A large pool of slow endpoints can exhaust that time budget before all models are attempted.

Provider quota errors still stop the whole request immediately. Existing provider cooldowns were deliberately retained by keeping the same runtime adapter version; routing updates never reset a quota. There are no new credentials, provider accounts, runtimes or model downloads.

An intermediate credential export/import attempt found no saved provider credential and did not solve the failure. That code was removed after the configuration comparison below established the actual cause. The final worker does not copy personal credentials or CLI session history.

## Resolved: CLI configuration rejection and normal conversation

Controlled comparisons established that the earlier free-limit response was caused by the LifeOS configuration. The normal CLI returned `OK`; the same CLI with isolated home/data/config and no account credentials also returned `OK`. Adding the catch-all global/agent `permissions` rules reproduced `provider.free-limit`/429. Removing those redundant rules while retaining the native `tool.use` deny policy made the LifeOS agent respond successfully. The earlier conclusion that this necessarily meant exhausted external quota was incorrect. Actual future provider quotas are still respected.

The supported CLI keeps its native tool definitions and denies execution through [OpenCode's native policy hook](https://github.com/anomalyco/opencode/blob/v2.2.5/packages/core/src/config/plugin/policy.ts). A real synthetic probe deliberately requested a shell write: both shell attempts, a directory listing, glob and read were rejected with `Blocked by configuration policy` and `executed: false`. No `policy-should-block.txt` was created. Evidence: excluded `tests/.tmp/cli-comparison/policy-result.json`. The credential-copy helper was removed because authentication was not the cause and no personal credential is needed for the verified free route.

Removed `steps: 1`, which injected a maximum-steps summary reminder into the first chat reply and could produce unwanted runtime commentary. The agent now requests only the final answer. Agent revisions invalidate answer caches separately from runtime metadata and provider cooldowns.

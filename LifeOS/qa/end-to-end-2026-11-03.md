# LifeOS 1.9.1 — startup, languages, profiles, work roles and AI

The user's installed folder existed at `%LOCALAPPDATA%/Programs/LifeOS` with its `data` directory and release metadata, but **LifeOS.exe and the application payload were absent**. This directly explains why that installation could not open. Its data is being preserved and backed up before reinstalling the application payload. The historical PHP log also recorded extension-path failures in a path containing spaces; current native startup was checked from the actual workspace path containing spaces and parentheses.

Implemented changes:

- Bounded startup readiness, PHP stderr/startup diagnostics, delayed background automation and OPcache in the production runtime. Per-request setting lookups are cached with write/rollback invalidation. The launcher does not wait synchronously for AI generation.
- Separate persisted WebView2 profiles for main/panel/university views. Switching disposes views from the old workspace, transfers only the authenticated target application session and retains external session cookies only within their original profile. Native tests use a stable synthetic external HTTPS origin for restart persistence; the random loopback port is intentionally a new application origin on each process launch.
- The WebView resize gesture now enters the Windows system sizing loop. Lock/sleep/resume handlers close private secondary windows and invalidate the application session. A lock event during profile switching is deferred until switching completes.
- Expanded Sinhala/Tamil dictionaries and server/client UI wiring, localized date names and appropriate Windows fonts. Submitted enum values, validation types, exact confirmation tokens and user records stay unchanged. Most added copy is machine translated: automated coverage and visual review do not constitute independent fluent human approval of every phrase.
- Work roles, responsibilities, recurring Today tasks, time recording/correction, daily logs, weekly summaries and explicit Money/Lessons links. See [Part 3](../docs/PART-3-WORK-ROLES-AI.md).
- Installed OpenCode CLI integration behind `AiProvider`: dynamic zero-cost discovery, restricted agent/credential isolation, asynchronous jobs, bounded retries/output, and confirmed allowlisted actions. No large runtime/model download was performed.

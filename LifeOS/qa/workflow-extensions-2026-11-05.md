# Workflow extensions — 2026-11-05

This source update addresses the requested language coverage, browser isolation, open-ended capture/notes, related failure themes, reliable routines and ICS recurrence. Source implementation is distinct from real-provider/account, fluent human and installer acceptance.

## Available workflows

- **Language:** new SI/TA catalog entries cover the missing account, Knowledge, workspace-transfer, routine and AI-review copy. Static view copy is wrapped without translating records, posted identifiers or protocol tokens. Browser catalogs are regenerated. New generated routine messages use translated templates with explicit values. Native window captions and tray commands follow the selected language. `scripts/audit_localization.py` checks literal PHP/browser/native translation keys and static view nodes without accessing user records; technical paths remain literal. It does not certify every possible dynamic/composite or upstream runtime message. Independent fluent Sinhala/Tamil human review remains pending and must not be represented as automated approval.
- **Profile browser storage:** main, desktop/AI panels and the university browser already use separate persisted named WebView2 profiles. Switch disposes old private views and transfers only the authenticated target local session. The historical report claiming external browser storage is shared is superseded. Native cookie/localStorage isolation, return switching and restart persistence are checked with synthetic origins, not personal university sign-in.
- **Own-words capture:** Quick Capture offers an AI suggestion flow in addition to the deterministic local parser. Typed text is sent online with an explicit disclosure. Open task IDs/titles/due dates are included only when selected. No balances, notes or other record collections are silently added. Model selection uses the existing verified-zero-cost runtime path; no runtime/model weights are installed. Proposed task creation/moves remain allowlisted, editable and explicitly confirmed. Move claims validate the queued task snapshot including deadlines/blocks; guarded moves retain undo previews. This is broad language interpretation for supported task actions, not unlimited action authority or a guarantee that any phrasing will be understood.
- **Notes:** select a saved note/transcript and explicitly share that text to request a summary and up to five proposed tasks. The original source is hashed; edits/deletion invalidate outstanding actions. Confirmed tasks retain source links. Responses are escaped, with loading/error/retry states. No records change merely because a summary arrives.
- **Related Failure Journal patterns:** local descriptive theme and vocabulary grouping complements exact normalized causes. It examines at most 250 entries in the stated 90-day window, shows source IDs/dates/excerpts, and offers a small preventive experiment. These are reviewable similarities, not proven causes, diagnoses or unrestricted semantic reasoning. No journal is sent online.
- **Routines:** optional task/focus completion and habit-check events are queued by database triggers. Event routines use custom reminders and start after their enable boundary. Each routine can choose an IANA timezone, 0–30 catch-up days, 0–3 retries and 1–1440 minutes retry delay. Defaults preserve no catch-up/retry. Transactions roll back action effects before recording a failure. Same action/period/timezone is claimed once across routines; event IDs distinguish activities. Processing is bounded to 100 enabled routines and 200 candidate slots per tick. Completed event pages cannot starve newer events. Exiting/sleeping the app still stops execution; opted-in catch-up evaluates missed dates after return, since routine creation only.
- **ICS recurrence:** php-rrule 3.0.0 handles bounded RRULE sets from secondly through yearly, including BYDAY/BYSETPOS, RDATE and EXDATE. RECURRENCE-ID supports individual moved/cancelled exceptions with stable original-occurrence identities and source wall-time/DST handling. New exclusions preview cancellation of previously imported occurrences; missing series are not silently deleted. Import uses an explicit range of at most two years and at most 500 resulting events, with a bounded scan. THISANDFUTURE time/duration/content shifts and finite subdaily series are supported within the same range/output limits. VTIMEZONE definitions require a recognized IANA TZID; custom zones are rejected. Attendee-bearing provider meetings remain provider-managed. This is bounded recurring import, not an unrestricted RFC calendar server.

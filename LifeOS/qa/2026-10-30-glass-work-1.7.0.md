# LifeOS 1.7.0: glass panel and Work options

## Delivered behavior

- The side panel is a floating inset window with a 26-pixel rounded native clip, Windows 11 Desktop Acrylic and transparent WebView backgrounds. Light/dark tables use time, title and type columns. Notes, to-dos, quick add, display preferences and auto-hide remain available. Hidden panel WebViews are suspended.
- **Win + \\** opens or closes the panel globally while LifeOS is running. The existing Ctrl+Shift+G shortcut also works. Windows notification and NIBM calendar behavior remain in place.
- Work provides Task, Bug, Story, Epic and Subtask types. Subtasks require a same-project parent; the types do not implement configurable type schemes or complete epic hierarchy rules.
- Project releases have dates, Planned/Released/Archived status, progress and version-checked edits. Issues can select a same-project Fix version. Release merge/notes and Affects version are not implemented.
- State WIP limits show the full active project count and an over-limit warning on the board. Limits are advisory and do not block moving a card.

## Installation and data

The release uses only the additive `Work/002_types_releases_wip.sql` migration. Existing issue/state values are compared using their original column sets, because the migration adds columns. Existing issues receive Task / no release; existing states receive no WIP limit; the new releases table starts empty. Before installation, a SQLite backup plus original-column hashes and upload hashes are saved. Installation excludes the existing data directory. Post-install evidence is recorded in `.tools/data-after-1.7.0.json`.

Installation completed on 2026-10-30. The pre-update backup is `C:/Users/USER/AppData/Local/Programs/LifeOS/data/backups/lifeos-before-1.7.0-glass-work-20261030.db`. All 76 existing user tables and 52 user rows matched their original-column hashes, all original migration history matched, the new release table is empty, and SQLite integrity/foreign-key checks passed. No uploads were present; the upload manifest matched. The installed executable reports version 1.7.0.

The Windows global hotkey registered successfully with native error 0. A real `SendInput` test (correct 40-byte x64 INPUT structure) sent Win+backslash twice: the panel changed visible → hidden → visible. Both four-key input sequences were accepted. Evidence: [.tools/panel-hotkey-result.json](../.tools/panel-hotkey-result.json). The app was left open with the panel shown.

Authenticated NIBM sign-in remains a user email/OTP action in the university WebView. Synthetic QA does not establish a live private NIBM response or full Jira parity.
